# Quest 3 — Publication and experience design brief

**Status: unpublished research preview implemented and QA-tested. Do not publish or claim the final research website is completed until the outgoing private spend and controls pass.**

## Research-led creative direction
Working title: **The First-Gas Question**.
Subtitle: **How does a new wallet receive, register and spend without a public balance?**
A high-craft, cinematic independent Rayls research journal that feels like a laboratory case study, not a marketing mockup or fabricated financial dashboard.

## Art direction
- Use the genuine Rayls symbol preserved at `site/assets/rayls-symbol-gradient.png`; verify brand accuracy against the official site. The research site's logo must be identified as independent work, not misrepresent official endorsement.
- Reuse the beloved Quest 1 dark-plum-to-purple theme: deep `#080611`, glass/plum `#151123`, lavender `#b69bf6`, acid-lime `#ecfb3e`, white `#f7f6ff`, restrained mint as evidence accent.
- Direction: cinematic but rigorously functional. Oversized editorial type, precision typography, a dramatic central light field, softly glowing transaction nodes, subtle film-grain dots, refined depth cues, and high contrast.
- Layered 3D scroll journey in 3 acts: `First funding` → `Who pays gas` → `Public proof`. Render comparison routes only after we have actual trials; diagrams based on docs must carry **illustrative** labels.
- Make public transaction traces interactive, allowing investigators to open a real explorer transaction, switch between evidence classes, compare gas/fee components and open exact source/ABI provenance, with number formatting and copy affordances.
- Give the evidence register a first-class place: live RPC verification state from stored run metadata, SHA-256 files, data class badges used sparingly, protocol versions, blocked tests and reproducibility commands. Never style public explorer observations as controlled experimental receipts.
- Motion: scroll-linked perspective transforms, 3D isometric vault scene with lazy-loaded particles, spring interpolation, performant compositing, high-frame-rate reveal, transition between public and shielded lanes, clickable tooltips and visual scientific controls. All animations purely illustrative unless bound to authenticated case data.
- Performance and accessibility: reduced-motion mode and pause button, keyboard navigation, no content hidden behind animation, accessible forms, touch devices, charts with text alternatives, interactive graphic depth reduction on mobile. QA at mobile/tablet/desktop, slow CPU/network, multi-browser and screenshot diffs.
- No third-party tracking, UTM marketing tags, copied visual templates, erroneous timeline labels, dead links, figure placeholders, or overwhelming page size.

## Site information architecture
1. Independent-research masthead, exact date, evidence edition, key finding sentence after actual experiment.
2. 3D journey with public funding, invitation, and direct shielded faucet routes.
3. Reconstructed public-chain receipts and source-gated event viewer, with controls highlighted.
4. True cost accounting for each path; separate relayer quotes from public ERC-20 transfers and actual gas paid.
5. What verified / what did not, including a prominent reviewer-friendly table for observation provenance.
6. Zero-trust reproducibility section: git clone, verify file manifest, rerun offline, rerun live, tamper tests.
7. Methodology, real control failures, raw evidence register, source references, browser/platform support.
8. A compact footer with unambiguous independent-research disclosure and citation links.

## Video plan (record after results)
- Video 1: official system + protocol flow + test accounts, safe screenshots / no sensitive keys.
- Video 2: real controlled lifecycles, fee accounting, failed controls, no fabricated transaction records.
- Video 3: fresh clone reproduction, live chain RPC verification, tamper-failure check, published website QA.
All terminal evidence must be paused/zoomed to readable size, captioned with provenance, and use concise voice scripts for optional narration.

## Editorial standard
Write a human, direct X Article, not a technical marketing brochure. Clean title; avoid generic AI phrasing, underlines, unnecessary hyphens, unlabeled on-chain claims, and questions inside the article. End with What verified, How to reproduce, Issues fixed, Sources visited, and three video placeholders. Publish any genuine team question in the separate attachment post.

## Pass/fail before publication
- New findings beyond docs and Nov 19 peer study; three route controls as executable, robust fault injection, full observation chronology.
- Case-specific tx hashes and explorer links verified by fresh RPC and tamper-resistant archive; claims are no stronger than evidence.
- No private links, credential material, personal data or live account secrets.
- Website and every asset publicly reachable at exact links: no 404, broken media, stalled webfont loads, clipping, interaction bugs, fake data or unresolved QA gaps.
- Final independent evaluator review against 98/100 feedback.
